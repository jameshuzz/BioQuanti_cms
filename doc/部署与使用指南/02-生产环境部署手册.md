## 3. 关键配置文件内容留存

### 3.1 /opt/mcms/mcms.sh（应用启停脚本）

```bash
#!/bin/bash
export JAVA_HOME=/opt/jdk17
export PATH=$JAVA_HOME/bin:$PATH
# BioQuanti CMS (MCMS 6.2.1) 启停脚本
# 用法: ./mcms.sh {start|stop|restart|status|log}

APP_NAME="BioQuanti-CMS"
APP_DIR="/opt/mcms"
JAR_FILE="$APP_DIR/ms-mcms.jar"
LOG_FILE="$APP_DIR/log/stdout.log"
PID_FILE="$APP_DIR/mcms.pid"
# JVM 内存: 3.6G 内存服务器用 512m 起步防 OOM
JAVA_OPTS="-Xms512m -Xmx1024m -XX:MaxMetaspaceSize=256m -Duser.timezone=Asia/Shanghai"

get_pid() {
    if [ -f "$PID_FILE" ]; then
        local pid
        pid=$(cat "$PID_FILE")
        if [ -n "$pid" ] && kill -0 "$pid" 2>/dev/null; then
            echo "$pid"; return 0
        fi
        rm -f "$PID_FILE"
    fi
    jps -l 2>/dev/null | grep "$JAR_FILE" | awk '{print $1}'
}

start() {
    local pid
    pid=$(get_pid)
    if [ -n "$pid" ]; then
        echo "[$APP_NAME] 已在运行 (PID: $pid)"; exit 0
    fi
    if [ ! -f "$JAR_FILE" ]; then
        echo "[$APP_NAME] 错误: 找不到 $JAR_FILE"; exit 1
    fi
    mkdir -p "$APP_DIR/log"
    # 关键: 工作目录必须是 /opt/mcms，模板/上传/静态页均按此目录相对解析
    cd "$APP_DIR" || exit 1
    nohup java $JAVA_OPTS -jar "$JAR_FILE" --spring.profiles.active=prod \
        >> "$LOG_FILE" 2>&1 &
    echo $! > "$PID_FILE"
    echo "[$APP_NAME] 启动中 (PID: $!)，日志: tail -f $LOG_FILE"
}

stop() {
    local pid
    pid=$(get_pid)
    if [ -z "$pid" ]; then
        echo "[$APP_NAME] 未在运行"; rm -f "$PID_FILE"; exit 0
    fi
    echo "[$APP_NAME] 正在停止 (PID: $pid)..."
    kill "$pid" 2>/dev/null
    local i=0
    while kill -0 "$pid" 2>/dev/null && [ $i -lt 30 ]; do
        sleep 1; i=$((i+1))
    done
    if kill -0 "$pid" 2>/dev/null; then
        echo "[$APP_NAME] 优雅停机超时，强制结束"
        kill -9 "$pid" 2>/dev/null
    fi
    rm -f "$PID_FILE"
    echo "[$APP_NAME] 已停止"
}

status() {
    local pid
    pid=$(get_pid)
    if [ -n "$pid" ]; then
        echo "[$APP_NAME] 运行中 (PID: $pid)"
        ps -o pid,vsz,rss,%cpu,etime -p "$pid" --no-headers
    else
        echo "[$APP_NAME] 未运行"
    fi
}

log() {
    tail -f "$LOG_FILE"
}

case "$1" in
    start)   start ;;
    stop)    stop ;;
    restart) stop; sleep 2; start ;;
    status)  status ;;
    log)     log ;;
    *) echo "用法: $0 {start|stop|restart|status|log}"; exit 1 ;;
esac
```

要点：**启动必须 `cd /opt/mcms`**（模板/上传/静态页路径相对解析）；`--spring.profiles.active=prod` 激活生产配置。

### 3.3 /etc/nginx/conf.d/mcms.conf（Nginx 站点配置）

结构总览（完整文件以服务器为准，修改前先备份到 `/opt/backup/`）：

```
HTTP :80
├─ zh.bioquanti.com   → 301 https://zh.bioquanti.com（SEO 文件放行）
├─ bioquanti.com      → 301 https://bioquanti.com（SEO 文件放行）
├─ www.bioquanti.com  → 301 https://zh.bioquanti.com（www 无证书仅 HTTP）
└─ default(IP/其他)   → 直接出中文站内容，不跳转

HTTPS :443
├─ zh.bioquanti.com   → 中文站（证书 zh.bioquanti.com_bundle.crt）
│    location = /            内部重写 /html/web/cn/index.html（URL 保持 /）
│    location /               root /opt/mcms/html/web/cn + try_files 回落动态
│    location /html|/template|/upload|/static   静态资源 alias
│    location = /robots.txt|/sitemap.xml       alias /opt/mcms/seo/
│    location /baidu_verify_  root /opt/mcms/seo
│    location = /index.html   301 归一化到 /
│    sub_filter '/html/web/cn/' '/'            URL 短链替换
└─ bioquanti.com      → 英文站（证书 bioquanti.com_bundle.crt，结构同上，en 目录）
```

关键机制说明：

1. **URL 短链**：页面代码里的 `/html/web/cn/` 前缀由 `sub_filter` 替换为 `/`，对外只暴露短地址；旧长地址通过 `location /html/` 保持兼容。
2. **静态直出**：静态页请求由 Nginx 直接读 `/opt/mcms/html/web/{cn|en}` 返回，不经过 Java；找不到才回落 8080 动态处理。
3. **SEO 文件**：`robots.txt`、`sitemap.xml`、百度验证文件统一放 `/opt/mcms/seo/`，由 Nginx 专用 location 发布，两个域名共用。
4. 修改配置后执行 `nginx -t && systemctl reload nginx`；配置修改前务必备份到 `/opt/backup/`（如 `mcms.conf.bak_20261010`）。

### 3.4 /etc/my.cnf（MySQL 关键参数）

## 4. HTTPS 证书

| 域名 | 证书 | 私钥 |
|---|---|---|
| zh.bioquanti.com | `/etc/nginx/cert/zh.bioquanti.com_bundle.crt` | `/etc/nginx/cert/zh.bioquanti.com.key` |
| bioquanti.com | `/etc/nginx/cert/bioquanti.com_bundle.crt` | `/etc/nginx/cert/bioquanti.com.key` |

续期流程（证书到期前，阿里云可免费申请一年期 DV 证书）：

1. 下载新证书（Nginx 格式，含 bundle crt 和 key）；
2. 备份旧证书到 `/opt/backup/cert_日期.tgz`；
3. 覆盖 `/etc/nginx/cert/` 下同名文件；
4. `nginx -t && systemctl reload nginx`（reload 即可，无需重启 nginx）；
5. 浏览器验证两个域名的 HTTPS 正常、锁标有效。

> 注意：如果前端挂了 CDN，需在 CDN 侧同步更新证书；当前架构 DNS 直接解析到源站，仅源站持有证书。

## 5. SEO 文件（百度收录）

全部位于 `/opt/mcms/seo/`，由 Nginx 专用 location 发布（无需重启应用）：

| 文件 | 说明 |
|---|---|
| `robots.txt` | `Sitemap: https://zh.bioquanti.com/sitemap.xml`（百度收录用中文站地址） |
| `sitemap.xml` | 全站 URL 清单（2026-10-11 版：1756 条，`https://zh.bioquanti.com/短路径` 格式） |
| `baidu_verify_codeva-w8B2Pkbh5u.html` | 百度站长平台站点验证文件（文件名固定，勿改名） |

**sitemap 重新生成方法**（网站栏目/文章大变动后执行）：

```bash
# 1. 扫描中文站全部静态页
cd /opt/mcms/html/web/cn && find . -name '*.html' | sed 's|^\./||' | sort > /tmp/cn_pages.txt

# 2. 生成 sitemap（首页写 /，因为 /index.html 会 301 归一化；其余保留原路径）
python3 - <<'EOF'
pages = [p.strip() for p in open('/tmp/cn_pages.txt') if p.strip().endswith('.html')]
base = 'https://zh.bioquanti.com/'
with open('/opt/mcms/seo/sitemap.xml', 'w') as f:
    f.write('<?xml version="1.0" encoding="UTF-8"?>\n<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">\n')
    for p in sorted(set(pages)):
        f.write(f'<url><loc>{base if p == "index.html" else base + p}</loc></url>\n')
    f.write('</urlset>\n')
print('done', len(set(pages)))
EOF
```

**提交收录**：百度站长平台（ziyuan.baidu.com）→ 普通收录 → 提交 `https://zh.bioquanti.com/sitemap.xml`。前台模板已内嵌百度自动推送 JS，页面被访问即自动推送。英文站走 Google Search Console（另生成 en 版 sitemap，方法同上换目录与域名）。

> 改动 SEO 文件后无需重启任何服务，Nginx 即时发布。可 `curl https://zh.bioquanti.com/robots.txt` 验证。

## 6. 标准发布流程（应用更新）

### 6.1 前置：本地打包

```bash
# 本地工作区根目录
mvn clean package -DskipTests
# 产物：target/ms-mcms.jar（约 160MB，含后台页面模板与前端资源）
```

### 6.2 发布步骤（生产）

```bash
# 1. 备份当前 jar（命名带日期）
cp /opt/mcms/ms-mcms.jar /opt/mcms/ms-mcms.jar.bak_$(date +%Y%m%d)

# 2. 上传新包（本地执行，先传 .new 避免半包）
scp target/ms-mcms.jar root@47.110.52.76:/opt/mcms/ms-mcms.jar.new

# 3. 原子替换 + 重启（生产执行）
mv /opt/mcms/ms-mcms.jar.new /opt/mcms/ms-mcms.jar
/opt/mcms/mcms.sh restart

# 4. 验证
/opt/mcms/mcms.sh status                          # 进程存在
tail -f /opt/mcms/log/stdout.log                  # 看到 "Started ... in x seconds"
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/html/web/cn/index.html   # 200
curl -s -o /dev/null -w '%{http_code}\n' https://zh.bioquanti.com/                      # 200
curl -s -o /dev/null -w '%{http_code}\n' https://bioquanti.com/                         # 200
```

### 6.3 同类更新：模板/静态资源

- 前台模板（`template/`）、上传文件（`upload/`）、SEO 文件（`seo/`）是**目录文件，不在 jar 内**，单独 scp 覆盖即可，无需重启应用；模板改动后需重新静态化。
- 后台页面模板（`WEB-INF/manager/**`）**打包在 jar 内**，改后台页面必须重打 jar。

### 6.4 回滚

```bash
# 用对应日期的备份包回滚并重启
cp /opt/mcms/ms-mcms.jar.bak_20261010 /opt/mcms/ms-mcms.jar
```

## 7. 数据库备份与恢复

- 实例：本机 MySQL，库 `mcms`，应用账号 `mcms / Bq#Cms2026@App`（root 仅本地）。
- 备份约定目录：`/opt/backup/`（现有备份：`mcms_full_bak_20261009.sql.gz` 等）。

```bash
# 全库备份（发布前必做）
mysqldump -umcms -p'Bq#Cms2026@App' --single-transaction --default-character-set=utf8mb4 mcms \
  | gzip > /opt/backup/db_bak_$(date +%Y%m%d_%H%M).sql.gz

# 单表备份（数据调整前，如产品规格表）
mysqldump -umcms -p'Bq#Cms2026@App' mcms mdiy_model_cpspecprod \
  > /opt/backup/cpspecprod_bak_$(date +%Y%m%d).sql

# 恢复全库
gunzip < /opt/backup/xxx.sql.gz | mysql -umcms -p'Bq#Cms2026@App' mcms

# 恢复单表
mysql -umcms -p'Bq#Cms2026@App' mcms < /opt/backup/cpspecprod_bak_xxx.sql
```

> **任何批量数据变更（导入、价格刷入、栏目调整）前，必须先备份涉及的表；生产数据变更建议按"货号"等业务键生成 SQL，避免依赖本地自增 ID。**

## 8. 全量静态化（重建所有静态页）

适用：模板大改、栏目结构调整、更换服务器后重建。输出在 `/opt/mcms/html/web/`。

**方式一：后台菜单**（内容管理 → 静态化）：逐站点执行"生成首页 + 生成栏目（选顶级，勾选含子级）+ 生成文章（时间选最早）"。

**方式二：脚本接口**（免登录批量执行，更快）：

```bash
# 登录拿 cookie（check-code=false 时验证码任意；为 true 需先临时改配置重启）
curl -s -c /tmp/ck.txt -X POST https://zh.bioquanti.com/ms/login.do \
  -d 'managerName=msopen&managerPassword=msopen&managerCode=1234'

# 依次生成：中文首页 → 中文栏目 → 中文文章；英文站换 en
```

## 9. 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 访问 502 | 应用没起来/端口未监听 | `/opt/mcms/mcms.sh status`；`tail -100 /opt/mcms/log/stdout.log` 看启动报错 |
| 启动后后台登录验证码图片 500 | 服务器缺字体组件（PDF/验证码渲染依赖） | `yum install -y fontconfig` 并安装中文字体后重启应用 |
| 应用运行数小时后卡死/被杀（OOM） | 内存不足 | 确认 JVM 参数为 `-Xms512m -Xmx1024m -XX:MaxMetaspaceSize=256m`；`free -h` 检查内存；建议配置 2G swap 且 `vm.swappiness=10` |
| 改了数据前台没变化 | 未静态化 / CDN 缓存 | 先静态化；CDN 控制台刷新对应目录缓存 |
| 域名打不开、IP 正常 | DNS 解析问题 | 阿里云云解析检查 A 记录是否指向 47.110.52.76；`ping 域名` 验证 |
| 证书告警/过期 | 未续期 | 按第 4 章续期 |
| 静态化报 `InvalidReferenceException: url` | 后台线程无 request 上下文 | 已修复（generateBasic 对 url 做兜底）；若复现检查 CmsParserUtil 代码 |
| 产品编辑页前端崩溃 | 自定义模型字段格式损坏（如 SPEC_PRICE 非合法 JSON） | 从备份表恢复该字段；格式要求见《系统使用操作手册》5.2 |

日志位置速查：启动/控制台 `log/stdout.log`；应用 `log/mcms.log`；错误 `log/error.log`（均在 `/opt/mcms/log/`，log4j 自动滚动）。

## 10. 安全与运维约定

1. **发布前必备份**：jar 发布备份 jar + 全库 dump；模板/配置修改备份原文件到 `/opt/backup/`（带日期后缀）。
2. **禁止在业务高峰批量静态化/批量生成附件**（占 CPU 与磁盘 IO）。
3. 后台账号最小化分配：运营只给内容管理权限；`mdiy:model:update`（更新模型=改表结构）仅限管理员。
4. 服务器 SSH 密码、数据库密码只在本手册与 doc/11.txtx 保存，勿在聊天工具/代码仓库外传；有人员变动及时改密。
5. swagger 已在生产关闭（application-prod.yml）；后台验证码校验如需开启改 `check-code: true` 重启。
6. 每次生产变更（发布/改配置/数据调整）在 `/opt/backup/` 留备份并在本目录追加变更记录，形成审计链条。
